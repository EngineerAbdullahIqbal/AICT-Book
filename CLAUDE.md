# AICT Course Guide

A Docusaurus teaching book for the 1-year AICT computer course for absolute beginners in
Pakistan. At first only the teacher (the owner) uses it, on a projector in class.

## Rules — read these first

The constitutions override this file. Read them before doing any work:

- `.specify/memory/constitution.md`: **how we build**. Spec Kit workflow, Test-First, small
  steps, no git by Claude.
- `specs/constitution.md`: **what we write**. Audience, simple English (Urdu optional), the
  verification rule, UNVERIFIED marking, quality standards. This is the single source for
  content rules; do not copy them elsewhere.

The non-negotiables, in short:

1. **Verify before you write.** Check Context7 before every command, config change or technical
   claim. For end-user software steps (Windows, Office, Adobe…), use the maker's official
   documentation. Never guess. If something can't be confirmed, stop and tell the owner.
2. **Test first.** Write the test, run it and see it **fail**, make the change, see it **pass**.
3. **Spec first.** No work without an approved spec → plan → tasks under `specs/`.
4. **Owner approves specs; reviews per module.** Wait for the owner's OK on every spec and lesson
   list. Then write the whole module's lessons and report: what was done, the docs used, how to
   check it, and the files changed. Then **wait for the owner's review**.
5. **Never invent** menu names, buttons or keyboard shortcuts. If a software step can't be
   verified, put it in a `:::warning[UNVERIFIED]` box (format in `specs/constitution.md` §4).
6. **No git.** Never run `git commit`, `git push` or publish anything. The owner commits and
   publishes to their own GitHub.

## Tech stack

- Docusaurus 3.10.2, classic template, **JavaScript** (not TypeScript), **npm**.
- Node.js ≥ 20.0 required (dev machine: v24.14.1, Ubuntu 24.04).
- Mermaid diagrams via `@docusaurus/theme-mermaid` (added in task T010).
- Playwright Test, Chromium only (added in tasks T001–T003).

## Commands

Run these inside `aict-guide/`:

| Command | What it does |
|---------|--------------|
| `npm run start` | Dev server at http://localhost:3000 (live reload) |
| `npm run build` | Production build into `build/`; fails on broken links |
| `npm run serve` | Serve the built site at http://localhost:3000 |
| `npm test` | Playwright tests; builds the site and serves it on port 3100 first. *Available after task T003.* |

## Workflow

- Spec Kit flow: `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` →
  `/speckit-implement`.
- **First release (2026-10-13)**: see `specs/book-spec.md` §9. Priority: Module 4 Word
  (`specs/module-04-ms-word/`), Module 7 Excel (`specs/module-07-ms-excel/`), then the Module 1
  lessons still missing (`specs/module-01-computer-basics/tasks.md`).
- Office steps (Word, Excel, PowerPoint) target **Office 2021** (Microsoft Support pages whose
  "Applies to" list includes 2021).
- Each lesson task runs: **RED** (add to `tests/lessons.js`) → **VERIFY** (facts + sources)
  → **GREEN** (write lesson, tests pass). The owner reviews each finished module.
- Windows steps must cover **Windows 10 and Windows 11**. Use
  `<Tabs groupId="windows-version">` where they differ. The owner tests UNVERIFIED steps on a
  Windows 11 laptop and a Windows 10 lab computer.
