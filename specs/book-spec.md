## 1. Purpose

A website-based teaching book for the 1-year AICT computer course for absolute beginners in
Pakistan. Students use the site to learn each lesson step by step, practise, and revise. Every
page must be readable by a complete beginner.

## 2. Users and How They Use the Site

**v1.2 (2026-10-13):** the **student** is the reader. The book may be shown in class, but every
page speaks to the student directly and never mentions the teacher.

| When | What the student does on the site |
|------|-----------------------------------|
| Learning | Reads Goal, Why It Matters and Key Terms, then follows **Step by Step** on a computer. |
| Practice | Does the **Practice** task alone, then compares with "Check your work". |
| Revision | Rereads Key Terms, answers the Check Questions, and reads Common Mistakes. |

Check-question answers are hidden until the student selects **Show answer** (v1.3), so students
think first.

### 2.3 User Scenarios (acceptance tests for the site as a whole)

1. **Find a lesson**: Given the teacher opens the site, when they open the sidebar, then they see
   all 16 modules in course order, and each module lists its lessons in teaching order.
2. **Teach a lesson**: Given a lesson page is open, when the teacher scrolls from top to bottom,
   then every lesson-template section appears in the same order as every other lesson.
3. **See a diagram**: Given a lesson page is open in a browser, when the page finishes loading,
   then every diagram is drawn as a picture (not shown as code).
4. **Spot risky steps**: Given a lesson contains a step that could not be checked, when the
   teacher reads it, then that step is inside a clearly marked UNVERIFIED box.

## 4. Lesson Template

Every lesson page has these sections, **in this order**, with these exact headings:

| # | Heading | Rules |
|---|---------|-------|
| 1 | **Goal** | One sentence that starts "By the end of this lesson, you can …". It names something the student can *do*, not just know. |
| 2 | **Why It Matters** | 2–5 short sentences, with at least two real-life examples from Pakistan (home, shop, office, school, jobs). |
| 3 | **Key Terms** | A table with 2 columns: Term → Simple meaning. A third column, Urdu meaning, is optional (lessons that already have it keep it). Every new word used in the lesson is here. 3–8 terms. |
| 4 | **Step by Step** | A worked example the student follows. Numbered steps, one action each. Each step (or group) says why you do it, and what you should see after it. |
| 5 | **Practice** | A new real-life task the student does alone. Numbered steps. Ends with "Check your work: …" saying exactly what a correct result looks like. |
| 6 | **Check Questions** | Exactly 3 questions. At least one asks the student to *do* or *point to* something, not only answer in words. Each has a model answer inside a `<details>` box whose `<summary>` is exactly "Show answer" (hidden until selected). |
| 7 | **Common Mistakes** | 2–5 items. Each item is: Mistake → How to fix it. |
| 8 | **Sources** | Every official source used to verify the lesson's technical claims (constitution, Section 3). |

Additional rules:
- The diagram(s) go wherever they help most, usually in Why It Matters, Key Terms or Teacher
  Demo.
- UNVERIFIED boxes appear only where needed, around the exact steps (constitution, Section 4).
- **Lesson length**: one lesson = one **60-minute** class session. Draft time plan (owner to
  confirm):

  | Part | Minutes |
  |------|---------|
  | Goal + Why It Matters + Key Terms | 10 |
  | Teacher Demo | 15 |
  | Student Task | 25 |
  | Check Questions + Common Mistakes | 10 |

  If a lesson cannot fit in 60 minutes, it is split into two lessons.
- **Urdu help**: optional, following `specs/constitution.md`, Section 1. Where Urdu is used, it
  is marked with `lang="ur"`.
- **Office version**: Microsoft Word and Excel steps target **Office 2016 / Office 2019** (the
  lab computers). Steps are checked against Microsoft Support pages for these versions.
- **Practice data**: Student Tasks show small tables on the page that students type in
  themselves. No downloadable practice files.
- **Screenshot spots**: where a screenshot would help, the lesson has a **hidden** note for the
  owner (an MDX comment). Students never see it. The owner later replaces it with a real
  screenshot:

  ```mdx
  {/* Screenshot to add: what the screenshot should show. */}
  ```

## 5. Diagram Standards

Verified capabilities (docs: Docusaurus *Markdown Features → Diagrams*, *theme-mermaid API*;
Mermaid *Accessibility*):
- Diagrams are written as Mermaid code blocks (a code block with the language `mermaid`).
  Docusaurus draws them when the `@docusaurus/theme-mermaid` theme is installed and
  `markdown.mermaid` is set to `true`.
- Mermaid diagrams support `accTitle` (accessible title) and `accDescr` (accessible
  description).
- Docusaurus lets you set a separate Mermaid theme for light mode and dark mode.

Rules:
1. **At least one diagram per lesson.** Add more wherever a picture explains better than words.
2. **Prefer flowcharts.** Use other diagram types only when a flowchart cannot show the idea.
3. **Keep it small**: no more than 8 boxes per diagram. If more are needed, split it into two
   diagrams.
4. **Simple labels**: 1–4 words per box, using only words that are explained in the lesson.
5. **One direction**: top-to-bottom or left-to-right, and the same direction within a lesson.
6. **Accessible**: every diagram has `accTitle` and `accDescr`.
7. **Diagram in words**: directly below each diagram, one or two plain sentences say what the
   diagram shows. This helps students who find diagrams hard, and helps the teacher explain it.
8. **Readable in both themes**: the diagram must be readable in light mode and dark mode.
9. **No decoration-only diagrams.** Every diagram must teach something.

## 6. Non-Goals (for now)

- No translations, no logins, no saved quiz scores, no video.
- Deployment: the site may be **configured** for GitHub Pages
  (`EngineerAbdullahIqbal/AICT-Book`). Only the owner publishes it.
- No lesson content for Modules 2–16 until each has its own approved spec. Module overview pages
  may list planned lessons and goals before that.

## 7. Book-Level Acceptance Criteria

- **BK-01**: The sidebar shows exactly 16 modules, in the order in Section 3.
- **BK-02**: Every lesson page has all 8 template sections, in order, with the exact headings
  from Section 4.
- **BK-03**: Every lesson page has at least one diagram that the browser draws as a picture.
- **BK-04**: Every diagram has `accTitle` and `accDescr`.
- **BK-05**: `npm run build` passes with zero broken-link, broken-anchor and broken-Markdown-link
  messages.
- **BK-06**: No page contains leftover starter content from the Docusaurus template (blog,
  tutorial pages).

How each one is tested (automated with Playwright or build checks, or by the owner) is decided
in the plan, following Test-First.

## 8. Risks

- **Official documentation gaps**: InPage Urdu and some free tools may have little official
  documentation, so those modules may have many UNVERIFIED steps for the owner to test.
- **Software versions**: menus differ between versions of Windows, Office and Adobe apps. Each
  module spec must name the version it targets.
